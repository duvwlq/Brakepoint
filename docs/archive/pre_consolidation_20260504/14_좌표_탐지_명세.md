# 14 Coordinate Detection Spec

## Goal

LMU DuckDB telemetry channels에서 실제 racing line으로 사용할 수 있는 좌표 데이터를 찾고, 사용할 수 없을 경우 명확한 fallback mode로 전환한다.

## Candidate Sources

좌표 후보 우선순위:

1. World X/Y 또는 World X/Z position
2. Vehicle Position X/Y 또는 Position X/Z
3. GPS latitude/longitude
4. none

## Candidate Channel Keywords

### X Candidates

- `World Position X`
- `Position X`
- `Pos X`
- `worldX`
- `position_x`
- `X`

### Y/Z Candidates

- `World Position Y`
- `World Position Z`
- `Position Y`
- `Position Z`
- `Pos Y`
- `Pos Z`
- `worldY`
- `worldZ`
- `position_y`
- `position_z`
- `Y`
- `Z`

### GPS Candidates

- `Latitude`
- `Longitude`
- `GPS Lat`
- `GPS Lon`
- `lat`
- `lon`

## Confidence Rules

### High

- x/y, x/z, 또는 lat/lon pair가 모두 존재한다.
- lap sample count가 충분하다.
- 값이 한 랩 동안 충분히 변한다.
- distance 또는 time 기준으로 정렬 가능하다.
- 비정상 점프가 적다.

### Medium

- 좌표 pair는 존재한다.
- sample count는 충분하다.
- 일부 구간에 missing value 또는 jump가 있다.
- warning을 표시하고 racing line을 그릴 수 있다.

### Low

- 좌표 pair는 있으나 sample count가 낮다.
- 값 변화가 작거나 불안정하다.
- 실제 racing line으로 신뢰하기 어렵다.
- UI에는 낮은 신뢰도 warning을 표시해야 한다.

### None

- x/y, x/z, lat/lon pair가 없다.
- `mode`는 `distance-graph-only`로 반환한다.
- 가짜 트랙맵을 만들지 않는다.

## Coordinate Validation

후보 좌표는 다음 조건으로 검증한다.

- min/max range가 충분히 넓은가?
- sample 값이 거의 상수인가?
- 0~1 범위 반복 normalized 값인가?
- 비정상적인 순간 jump가 많은가?
- distance 증가와 함께 위치 변화가 자연스러운가?
- 한 lap의 시작/끝 위치가 물리적으로 가까운가?

## GPS Projection

GPS latitude/longitude가 발견되면 별도 평면 좌표 변환이 필요하다.

MVP에서는 probe 결과 전까지 projection 방식을 확정하지 않는다.

## Output

```ts
type CoordinateDetectionResult = {
  hasCoordinates: boolean
  source: 'world' | 'position' | 'gps' | 'none'
  confidence: 'high' | 'medium' | 'low' | 'none'
  xChannel?: string
  yChannel?: string
  latChannel?: string
  lonChannel?: string
  reason: string
}
```

## Fallback Rule

좌표가 없거나 confidence가 `none`이면:

- Racing line을 표시하지 않는다.
- SVG나 임의 path로 가짜 track map을 만들지 않는다.
- 가능한 경우 Speed / Brake / Throttle graph만 표시한다.
- UI에 `Coordinate Data Missing` 또는 동등한 명확한 메시지를 표시한다.
