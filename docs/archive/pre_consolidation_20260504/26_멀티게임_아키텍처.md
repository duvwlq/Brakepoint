# 26 멀티게임 아키텍처

## Principle

Brakepoint는 게임별 telemetry 구조를 UI나 분석 로직에 직접 노출하지 않는다.

각 게임은 Game Adapter를 통해 raw telemetry를 Brakepoint canonical model로 변환한다.

## Current Focus

Phase 1은 LMU DuckDB adapter만 구현한다.

## Future

F1 25, Assetto Corsa, Assetto Corsa Competizione, iRacing 등은 Phase 7 이후 adapter로 추가한다.

## Architecture

```text
Game-specific Source
  -> Game Adapter
  -> Raw Ingest
  -> Normalize
  -> Brakepoint Canonical Session Store
  -> Domain / Analysis Layer
  -> UI
```

## Source Examples

| Game | Source | Mode |
| --- | --- | --- |
| LMU | DuckDB file | post-session |
| F1 25 | UDP stream | live capture -> stored session |
| Assetto Corsa | shared memory | live capture -> stored session |
| ACC | shared memory / broadcast APIs | live capture -> stored session |
| iRacing | SDK / memory mapped / IBT-like logs | live or post-session |

## Rule

- 새 게임 지원은 새 앱 구조를 만들지 않는다.
- 새 Game Adapter와 mapping manifest를 추가한다.
- UI는 canonical model만 사용한다.
- Cross-game comparison은 기본 금지다.

## Phase 1 Boundary

멀티게임 구조는 문서화하지만 구현은 LMU adapter만 한다.
