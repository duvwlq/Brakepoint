# 08 아키텍처

## 1. Runtime

Brakepoint는 Electron 데스크톱 앱이다.

```text
React Renderer
  -> window.brakepointApi
  -> Electron Preload
  -> Electron Main IPC
  -> Game Adapter
  -> Data Engine
```

## 2. Architecture Flow

```text
Game-specific Source
  -> Game Adapter
  -> Raw Ingest
  -> Normalize
  -> Brakepoint Canonical Session Store
  -> Domain / Analysis Layer
  -> UI
```

## 3. Layers

### Game Adapter Layer

역할:

- 게임별 source 탐지
- raw telemetry probe
- session/lap loading
- unit normalization
- coordinate normalization
- capability report
- warning/fallback 생성

Phase 1에서는 `lmuDuckdbAdapter`만 구현한다.

### Data Layer

역할:

- file system 접근
- DuckDB read-only 연결
- raw table access
- metadata/channel/event table 탐색
- 향후 internal session store 접근

### Domain Layer

역할:

- metadata parsing
- lap extraction
- coordinate detection
- distance alignment
- canonical telemetry model 생성
- `RacingLinePoint[]` 생성
- graph-ready data 생성

### Rendering Layer

역할:

- Canvas draw
- fit-to-view
- racing line draw
- marker draw

### UI Layer

역할:

- React state
- user interaction
- IPC call
- error/fallback 표시

## 4. Rules

- Canvas는 계산하지 않는다.
- React component는 DuckDB table 구조나 UDP packet 구조를 알면 안 된다.
- Game Adapter 밖의 UI/Domain은 게임별 raw field 이름에 의존하면 안 된다.
- 좌표가 없으면 fallback을 반환한다.
- Renderer는 filesystem/DuckDB/shared memory/UDP에 직접 접근하지 않는다.
- 모든 sync 기준은 가능한 경우 distance다.
- MVP 이후 기능은 Phase Gate를 통과한 뒤에만 architecture에 반영한다.

## 5. Boundary

```text
DuckDB / UDP / shared memory / SDK raw schema
  -> Game Adapter에서만 사용

Canonical models
  -> Domain/UI에서 사용
```

UI는 `NormalizedSessionSummary`, `NormalizedLapSummary`, `RacingLineViewData` 같은 contract model만 알면 된다.
