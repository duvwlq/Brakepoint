# 12 Research Plan

## 1. Goal

Brakepoint Phase 1 개발 전에 아이디어와 실제 LMU telemetry 데이터가 충돌하지 않도록 조사 범위를 고정한다.

이 단계에서는 앱 기능을 구현하지 않는다.

## 2. Research Principle

```text
로드맵은 크게 설계한다.
구현은 Phase Gate를 통과한 기능만 한다.
```

## 3. LMU Telemetry Research

확인 항목:

- Telemetry recording 활성화 방식
- 기본 저장 위치
- 파일명 규칙
- DuckDB 파일 생성 조건
- 자동 기록과 수동 기록 차이
- 세션 종료 전 파일 완성 여부
- `.wal` 파일 처리
- 손상/미완성 파일 케이스

## 4. DuckDB Schema Research

실제 `.duckdb` 파일에서 확인할 항목:

- table list
- column list
- row count
- metadata 위치
- Lap event 위치
- Lap Time event 위치
- distance 후보
- time 후보
- XY 후보
- GPS 후보
- speed 후보
- brake 후보
- throttle 후보
- steering 후보
- 단위
- null 비율
- sample rate
- 값 변화 범위

세부 기준은 `13_DuckDB_데이터_조사.md`를 따른다.

## 5. Coordinate Research

가장 중요한 조사 항목:

- XY 좌표가 있는가?
- GPS 좌표가 있는가?
- 둘 다 있는가?
- 좌표값이 track/world coordinate인가?
- GPS면 lat/lon을 평면 좌표로 변환해야 하는가?
- 좌표가 lap boundary 안에서 연속적인가?
- distance와 정렬 가능한가?
- 좌표가 없는 세션이 있는가?
- 트랙/차량/세션 타입마다 channel명이 다른가?

세부 기준은 `14_좌표_탐지_명세.md`를 따른다.

## 6. Product/UX Research

비교 대상:

- MoTeC
- SimHub
- MyLMU telemetry
- simtelemetry.site
- 기존 LMU telemetry visualizer

조사 기준:

- 초보자가 이해하기 쉬운가?
- racing line이 중심인가?
- graph가 너무 복잡하지 않은가?
- hover sync가 있는가?
- best lap 비교를 어떻게 보여주는가?
- coach 문장을 어떻게 제공하는가?

## 7. Design Research

확인 항목:

- LMU 이미지에서 영감 받은 palette
- Brakepoint만의 독립 브랜드 톤
- dark theme readability
- red/blue contrast
- color-blind safe 표시
- line thickness
- marker shape
- warning badge
- data confidence badge

디자인 시스템은 `15_디자인_시스템.md`를 따른다.

## 8. Research Output

Phase 0 완료 시 다음이 있어야 한다.

- DuckDB probe report
- Coordinate detection 판단 기준
- Idea/Data Alignment Matrix
- Phase Gate 결과
- SRS/Data Model/API 보강 필요 목록

## 9. Open Questions

- 실제 LMU DuckDB 좌표 channel이 모든 session에 존재하는가?
- 좌표가 GPS인지 world position인지 확인 필요.
- Speed/Brake/Throttle channel 단위와 범위 확인 필요.
- Lap boundary와 Lap Time event mapping 안정성 확인 필요.
