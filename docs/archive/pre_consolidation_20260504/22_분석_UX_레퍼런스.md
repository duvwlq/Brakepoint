# 22 분석 UX 레퍼런스

## 1. 목적

Brakepoint의 분석 UX는 telemetry로 검증된 지표만 보여준다.

검증되지 않은 insight는 표시하지 않는다.

## 2. Phase 1 UX

목표:

내가 실제로 어떻게 달렸는지 본다.

포함:

- Racing Line Canvas
- Hover marker
- Distance tooltip
- Speed graph
- Brake graph
- Throttle graph
- Data mode badge
- Coordinate confidence
- Coordinate missing fallback

화면 원칙:

```text
Racing Line이 중심
Graph는 보조
```

## 3. Phase 2 UX

목표:

Current lap과 Best Lap의 차이를 distance 기준으로 본다.

포함 가능:

- Current vs Best Lap overlay
- Distance aligned delta
- Speed / Brake / Throttle comparison
- Graph-only comparison fallback

Gate:

- 두 lap의 distance alignment가 안정적이어야 한다.
- valid lap mapping이 안정적이어야 한다.

## 4. Phase 3 UX

목표:

두 차량의 움직임 차이를 직관적으로 본다.

포함 가능:

- Ghost replay
- Distance playhead
- Current / Ghost marker
- delta time display

Gate:

- distance-indexed interpolation 가능
- replay 성능 확인

## 5. Phase 4 UX

목표:

사용자가 어디를 봐야 하는지 앱이 알려준다.

포함 가능:

- Focus Zone
- Biggest loss area
- Brake / throttle / speed difference marker
- line deviation marker

Gate:

- brake start, throttle reapply, min speed, exit speed 계산 가능
- 잘못된 focus를 막는 confidence rule 존재

## 6. Phase 5 UX

목표:

다음 랩에서 무엇을 바꿔야 하는지 알려준다.

포함 가능:

- Rule-based Coach Flow
- Root cause explanation
- Top 1 action
- Top 3 improvements

금지:

- telemetry 근거 없는 조언
- AI가 판단의 source of truth가 되는 구조
- 데이터가 불안정한데 확정적인 코칭 문장 표시

## 7. UX Rule

분석 UX는 다음 질문에 답해야 한다.

```text
내가 어디를 보고 있는가?
그 지점에서 어떤 입력을 했는가?
이 데이터는 실제 좌표 기반인가?
이 기능은 현재 Phase에서 검증됐는가?
```

## 8. MVP Boundary

Phase 1에서는 Focus Zone, Coach, Ghost를 구현하지 않는다.

Phase 1의 핵심은 실제 주행 라인을 정확하게 보여주는 것이다.
