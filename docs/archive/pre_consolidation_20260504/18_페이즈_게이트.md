# 18 페이즈 게이트

## Goal

로드맵과 실제 개발이 충돌하지 않게 각 Phase의 진입 조건을 정의한다.

## Phase 0 Exit Gate

Phase 1 개발을 시작하려면 다음이 완료되어야 한다.

- DuckDB schema probe 완료
- 좌표 후보 channel 확인
- distance 후보 확인
- speed/brake/throttle 후보 확인
- CarName / CarClass metadata 확인
- SessionType metadata 확인
- RaceResult 기록 여부 조사
- fallback 정책 확정
- design token 확정
- canonical telemetry model 확정
- Game Adapter contract 확정
- `05_데이터_모델.md` / `06_API_계약.md` / `07_수락_테스트.md`가 probe 결과와 충돌하지 않음

## Phase 1 Entry Gate

조건:

- Phase 0 Exit Gate 통과
- 좌표가 있는 sample session 1개 이상 확인
- 좌표가 없는 sample session fallback 확인
- invalid lap sample 확인 또는 mock 조건 정의
- 서로 다른 track/layout sample 2개 이상에서 racing line fit-to-view 확인
- 긴 track과 짧은 track/layout에서 distance graph 정상 표시
- hardcoded track map 없이 좌표 기반 rendering 가능 확인
- session detail에서 carName / carClass / sessionType 표시 가능
- RaceResult가 없을 경우 추측하지 않는 fallback 정책 확인

## Phase 2 Entry Gate

조건:

- Phase 1 안정 동작
- current lap과 best lap 모두 distance alignment 가능
- 두 lap의 sample interpolation 가능
- line overlay 성능 확인
- graph-only comparison fallback 정의
- comparison compatibility rule 존재

## Phase 3 Entry Gate

조건:

- 두 lap replay interpolation 가능
- distance 기준 playhead 안정화
- delta time 계산 가능
- Canvas 성능 확인

## Phase 4 Entry Gate

조건:

- brake start 계산 가능
- throttle reapply 계산 가능
- min speed / exit speed 계산 가능
- line deviation 계산 가능
- 잘못된 insight를 막는 confidence rule 존재

## Phase 5 Entry Gate

조건:

- Phase 4 분석 지표 안정화
- Top issue 선정 기준 존재
- rule-based 문장 template 존재
- AI 없이 coach message 생성 가능

## Phase 6 Entry Gate

조건:

- 다수 lap XY 데이터 확보
- lap별 coordinate alignment 가능
- outlier 제거 기준 존재
- track envelope 추정이 사용자에게 오해를 주지 않는다는 검증 필요

## Phase 7 Entry Gate

조건:

- LMU MVP 안정화
- 새 game telemetry source 조사 완료
- Game Adapter probe 완료
- GameCapabilities matrix 작성
- canonical telemetry mapping 검증
- live capture / post-session import 방식 확정
- legal/API 제한 확인
- 기존 data model/API가 확장 가능한지 검토

## Rule

Gate를 통과하지 않은 Phase의 기능은 구현하지 않는다.

필요하면 문서에 `Future` 또는 `Blocked by data`로 기록한다.
